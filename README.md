# Sharp Overlay — прототип для замера задержки

## Что это

Android-приложение, которое:
1. Захватывает экран через `MediaProjection` (как приложения записи экрана)
2. Прогоняет каждый кадр через один из трёх GLSL-шейдеров резкости (CAS / RCAS / Dynamic Sharp)
3. Выводит результат через полноэкранный system overlay поверх исходного экрана

Три режима переключаются в приложении, интенсивность регулируется слайдером в реальном времени.

## Как собрать (под Android 16 / API 36)

Нужен **Android Studio Meerkat (2024.3.1+) или новее** + SDK Platform 36.

1. Открой Android Studio → **File → Open** → выбери папку `SharpOverlay`
2. Studio сама предложит докачать Android 16 SDK (Platform 36) и сгенерирует `gradle-wrapper`
3. Дождись синхронизации Gradle
4. **Build → Build Bundle(s) / APK(s) → Build APK(s)**  
   или в терминале внутри Studio:
   ```bash
   ./gradlew assembleDebug
   ```

Готовый APK:  
`app/build/outputs/apk/debug/app-debug.apk`

Если Studio старая и ругается на AGP 8.7 — можно временно поставить `compileSdk 35` / `targetSdk 35`. Приложение всё равно будет нормально работать на Android 16.

## Как пользоваться

1. Открой приложение → "Запросить overlay-разрешение" → разреши в системных настройках
2. Выбери режим (CAS / RCAS / Dynamic Sharp) и интенсивность
3. "Запустить захват экрана + фильтр" → система спросит подтверждение на запись экрана → разреши
4. Сверни приложение и запусти игру — весь экран должен идти через фильтр

## ВАЖНО: что может не сработать с первого раза

Это прототип, собранный для тестирования, а не production-приложение. Три места, где реально может понадобиться доработка под конкретный телефон:

**1. Перекрытие исходного кадра.**
Overlay рисуется поверх системы, но Android не гарантирует, что `TYPE_APPLICATION_OVERLAY` с `PixelFormat.OPAQUE` физически перекроет вообще весь кадр без единого просвета (статус-бар, системные жесты, edge-to-edge вырезы могут вести себя по-разному на разных прошивках/API уровнях). Если увидишь двоение картинки — это оно.

**2. VirtualDisplay может поймать сам оверлей в рекурсию.**
`MediaProjection` захватывает весь экран, включая уже нарисованный overlay поверх него — если это произойдёт, ты увидишь "зеркальный коридор" (картинка в картинке). Обычно `VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR` этого не делает для окон другого процесса, но если увидишь такой эффект — исправление: `windowManager.LayoutParams` флаг для исключения own-window из захвата, либо рендерить в offscreen FBO и не показывать overlay пока не готов первый кадр.

**3. Разрешения на новых Android.**
На Android 14+ `FOREGROUND_SERVICE_MEDIA_PROJECTION` обязателен в манифесте (уже добавлен) и система может показывать доп. диалог при старте сервиса. На некоторых прошивках (MIUI, ColorOS, One UI) overlay-разрешение называется иначе ("Отображать поверх других окон" / "Всплывающие окна") — ищи в настройках приложения вручную, если системный диалог не откроет нужный экран.

## Как честно замерить задержку

Самый простой способ без доп. оборудования:

1. Установи любой FPS/задержка-счётчик, который рисует **быстро меняющийся счётчик кадров** на весь экран (например, тестовые паттерны из `Testufo.com` в браузере — там есть UFO-тест на задержку ввода, либо просто секундомер с миллисекундами)
2. Сними на **другой телефон в замедленной съёмке (960 fps если поддерживается)** экран, на котором одновременно видно и исходный дисплей, и то же самое через зеркало/отражение — это классический метод замера input lag
3. Посчитай разницу кадров между "живым" изменением числа и изменением, прошедшим через фильтр

Проще: включи любую игру с встроенным счётчиком FPS и посмотри на **субъективную задержку отклика** при свайпах/тапах в быстрых играх (ритм-игры вроде osu!, файтинги) — там задержка в 2-3 кадра (33-50мс при 60fps) будет отчётливо "ощущаться пальцами", даже если глазами разницу в картинке не поймать.

## Если задержка окажется неприемлемой

Как обсуждали — узкое место архитектурное (путь: GPU игры → композитор → MediaProjection → GL обработка → overlay → композитор снова), а не в шейдерах. Если лаг критичен для твоих игр:

- Для **неторопливых игр** (стратегии, JRPG, визуальные новеллы) — вероятно, останется играбельно
- Для **динамичных игр** — единственный путь без задержки это либо root+Magisk модуль (RootlessFSR/аналоги, патчит Vulkan-слой самой игры без прохода через overlay), либо игры со встроенной поддержкой FSR

## Структура проекта

```
app/src/main/
├── AndroidManifest.xml          — разрешения (overlay, media projection, foreground service)
├── assets/shaders/
│   ├── vertex.glsl              — общий вершинный шейдер
│   ├── cas.glsl                 — упрощённый CAS (5 сэмплов, адаптивный вес)
│   ├── rcas.glsl                — упрощённый RCAS (с защитой от ореолов)
│   └── dynamic_sharp.glsl       — минимальный unsharp mask (самый дешёвый)
├── java/com/example/sharpoverlay/
│   ├── MainActivity.kt          — UI, запрос разрешений
│   ├── SharpCaptureService.kt   — foreground service: EGL + MediaProjection + overlay
│   └── GLRenderer.kt            — компиляция шейдеров, рендер кадра
└── res/                         — layout и минимальные ресурсы
```

## Сборка через GitHub Actions (рекомендуется)

1. Создай новый репозиторий на GitHub
2. Загрузи содержимое этой папки (можно через веб-интерфейс или `git push`)
3. Перейди во вкладку **Actions**
4. Запусти workflow **Build APK** (кнопка "Run workflow")
5. После успешной сборки скачай артефакт **SharpOverlay-debug** — там будет `.apk`

Или просто сделай `git push` в `main`/`master` — сборка запустится автоматически.

### Локальная сборка (если есть Android SDK)

```bash
chmod +x gradlew
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`
